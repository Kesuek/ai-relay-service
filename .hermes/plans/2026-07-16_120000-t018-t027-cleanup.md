## Task 7: T-026 — Capabilities normalisieren

**Objective:** `capabilities` als TEXT JSON in `nodes`-Tabelle erschwert effizientes Matching. Separate Tabelle `node_capabilities` einführen.

**Files:**
- Modify: `src/relay_server/core/db.py` (neue Tabelle + Migration)
- Modify: `src/relay_server/core/node_registry.py` (Capabilities aus neuer Tabelle lesen/schreiben)
- Modify: `src/relay_server/core/scheduler.py` (Capability-Matching anpassen)

**Änderungen:**

1. Neue Tabelle `node_capabilities` in `_schema()`:
```sql
CREATE TABLE IF NOT EXISTS node_capabilities (
    node_id TEXT NOT NULL,
    capability_name TEXT NOT NULL,
    capability_version TEXT DEFAULT '1.0.0',
    available BOOLEAN DEFAULT 1,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (node_id, capability_name),
    FOREIGN KEY (node_id) REFERENCES nodes(node_id) ON DELETE CASCADE
)
```

2. Migration für bestehende Daten: `capabilities` TEXT JSON → `node_capabilities`-Rows
3. `NodeRegistry` liest/schreibt Capabilities aus neuer Tabelle
4. `Scheduler.claim_stage()` matched über `node_capabilities` statt `json.loads(capabilities)`

**Commit:**
```bash
git add src/relay_server/core/db.py src/relay_server/core/node_registry.py src/relay_server/core/scheduler.py
git commit -m "feat(db): normalize capabilities into separate node_capabilities table"
```
