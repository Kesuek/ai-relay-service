## Task 1: T-041 — Handler-Fehlerdiagnose verbessern

**Goal:** Handler-Exit-Code, stdout/stderr und Exception-Traceback im Stage-Result sichtbar machen. `node-cli task result` zeigt dann nicht nur `"answer": ""` sondern auch was schiefging.

**Files:**
- Modify: `nodes/common/handler_runner.py` (bereits gut, nur kleine Ergänzung)
- Modify: `nodes/common/node_cli.py` (`_print_task_result` zeigt result detaillierter)
- Modify: `~/.relay/handlers/hermes-handler.py` (bereits aktualisiert mit debug-Feld)

**Step 1: `handler_runner.py` — stderr immer mitschicken**

Aktuell wird stderr nur bei non-zero exit mitgeschickt. Ändere `run_handler()` so, dass bei erfolgreichem Exit (0) ebenfalls `stderr` und `stdout_length` im Result landen:

```python
# Nach Zeile 166 (return parsed)
# Vor dem return parsed:
if isinstance(parsed, dict):
    parsed.setdefault("_handler", {})
    parsed["_handler"]["stderr"] = stderr
    parsed["_handler"]["stdout_length"] = len(stdout)
    parsed["_handler"]["exit_code"] = proc.returncode
return parsed
```

**Step 2: `node_cli.py` — `_print_task_result` erweitern**

In `_print_task_result()` nach der Stage-Ausgabe auch `_handler`-Debug-Infos anzeigen wenn vorhanden:

```python
# Nach der Stage-Schleife, vor Artifacts:
handler_info = s.get("result", {}).get("_handler")
if handler_info:
    print(f"      [handler] exit={handler_info.get('exit_code')} "
          f"stdout={handler_info.get('stdout_length','?')}B "
          f"stderr={handler_info.get('stderr','')[:200]}")
```
